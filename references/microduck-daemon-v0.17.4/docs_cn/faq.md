# 常见问题（FAQ）

当你希望鸭子做一些它开箱并不能做的事情时，会遇到的这些问题。设计文档讲的是机制如何运转；这一页告诉你该去拿哪一块拼图。

## 我想运行一个对这块开发板来说太重了的模型

到别处运行它，然后把摄像头画面发给它。这块开发板是 Radxa Zero 3——NPU 只能容纳一个小型检测器，再多就吃力了——所以任何更大的模型都应该放到机器人之外，而在付费硬件上运行一个 Hugging Face Space 是要搭建最少的一条路：它自带 GPU 选项、机器人共享的账户体系，以及一个 URL。

**使用 WebRTC。** 机器人通过一个 WebRTC 会话发布 H.264，你的 Space 消费它，而 rendezvous 服务负责牵线，让两者都无需知道对方的地址。`spaces/vision-demo/` 就是一个完整的示例。

```
你的 Space ──登录、列出机器人──►  rendezvous  ◄──注册──  鸭子
你的 Space ◄═══════════ H.264 over WebRTC，媒体与控制 ════════════►  鸭子
```

坚持使用 WebRTC，你能免费获得三样东西，而它们正是它成为默认选择的原因：媒体由 DTLS-SRTP 端到端加密；控制通道与媒体走同一个会话，所以你既能观看也能*驾驶*；而且它有一条回传路径——音频，或第二条视频轨——等你哪一天想要。

## 从数据中心能用吗？我的 Space 在一个我无法控制的 NAT 后面

可以。家庭路由器后面的机器人，与数据中心 NAT 后面的容器，通常无法互相打洞，因此机器人会提供一个**中继候选**——它用自己的账户令牌临时签发的 Cloudflare 凭证——而你的消费端使用它时无需自己持有任何凭证。`remote-access-design.md` §6 讲的就是这个机制。

有两点值得提前知道，免得被吓到：

- **中继消耗的是机器人主人的带宽**，按 Hugging Face 账户计量，免费档每月 10 GB。连续 720p 流大约每小时 1 GB，所以一个整天都在观看的 Space 会把它用完。ICE 只在必要时才走中继——能找到直连就会用直连——但在家庭与数据中心之间，「必要」是很常见的。
- **浏览器消费端在没有自己的 IPv4 时，需要自己的中继凭证**；Python 消费端则不需要。§6 里有这个情形。

## 我的消费端是一个程序，而且流整天都在跑。有没有更便宜的办法？

有一个后备方案，而且它确实只是后备，而不是第二套设计：**`media.stream`**——机器人主动拨号到*你的* WebSocket，并把帧向外推送。

```
你的 Space ──media.stream {url: "wss://…/frames"}──►  rendezvous  ──►  鸭子
鸭子   ══════════ 帧，出站 wss，直连 ══════════════►  你的 Space
```

它不消耗任何人的中继，因为机器人发出的出站连接不需要打洞。当以下三点同时成立时使用它：消费端是一个**程序**而不是人；流**足够长**以至于中继计量是个问题；而且你只需要**帧**。

离开 WebRTC 后你会失去什么，正是它不成为默认的原因：

- **完全没有回传路径。** 在这条传输上没有任何东西能到达机器人——没有音频、没有第二条视频轨、没有遥操作闭环。
- **没有控制通道。** 驾驶机器人意味着通过 rendezvous 单独发一次 JSON-RPC 调用（`spaces/shared/wire.py`）。
- **加密是你的 TLS，而不是 DTLS-SRTP**，而且它终止在你的服务器端，而不是对端。

机器人会先发送一条文本 **hello** 来描述接下来是什么——`frames.encoding` 是 `h264` 或 `jpeg`——然后每个帧一条二进制消息。请根据 hello 来分支，而不是去嗅探字节；`spaces/vision-demo/receiver.py` 是参考接收端，`decoder_for` 就是那个分支。

## 我的 Space 怎么找到机器人？又是什么阻止别人连到它？

是账户。机器人持有自己的 Hugging Face 令牌向 rendezvous 注册，你的 Space 用 `hf_oauth` 给访客登录，而服务只会向账户展示它所拥有的机器人。机器人上无需任何配置，也不涉及机器人端的门禁——`remote-access-design.md` §7 论证了为什么这样就够了。

`spaces/shared/rendezvous.py` 是列举调用：`ducks(token)` 给你该账户所能触达的对象。

## 没有机器人我能测试吗？

`scripts/duck-sim` 会让真正的守护进程驱动一个 MuJoCo 身体（[`robot/simulation.md`](robot/simulation.md)）。它像开发板一样向 rendezvous 注册，并标记为模拟，所以你的 Space 访问它的方式与访问真实机器人完全一致。
