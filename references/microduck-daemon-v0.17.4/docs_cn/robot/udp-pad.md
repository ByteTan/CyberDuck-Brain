# 用 UDP 手柄驾驶

同一网络上的一个程序把手柄的状态——摇杆、扳机、按键——作为 UDP 数据报发出，机器人对它做的和它对蓝牙手柄做的完全一样：同样的映射、同样的方向键模式、同样的 Start 和 Select 长按。它给一只不靠近机器人的手柄，或根本就不是蓝牙的——一台 USB 口插着手柄的笔记本、一部手机、一个脚本。`netpadd` 是监听的守护进程；`padd` 是通过蓝牙读手柄的那个，二者一次恰好运行一个（见[机器人做什么](#机器人做什么)）。

**它是一个快速的、无认证的局域网工具，只为一个情形而造：在一条你信任的网络上，一只手柄以尽可能低的延迟驾驶机器人。** 网络上任何够得到那个端口的人都能驾驶机器人、让它站起来、坐下和断电——见[信任](#信任)。它不是一般控制机器人的方式：那是 WebRTC，它经过认证和加密、带一条回传路径、且能从局域网外工作——[`../design/remote-webrtc.md`](../design/remote-webrtc.md)。

配对一个蓝牙手柄是另一回事，见 [`pair-a-gamepad.md`](pair-a-gamepad.md)。

## 打开它

默认关闭。只有在你清楚它打开的是什么、在一条你信任的网络上时才打开它。

一旦打开，**它保持打开**——跨重启和更新——直到你再关掉它：它是一个配置键，不是一个会话。它开着时，端口是开的，蓝牙手柄不工作。

在配置里打开它：

```bash
sudo robotctl configure
```

设 `netpad.enabled = true`，然后重启两个守护进程：

```bash
sudo systemctl restart padd netpadd
```

两个都要，因为每个都在启动时决定自己是不是该运行的那个：`[netpad] enabled` 为真时 `padd` 退下，不为真时 `netpadd` 退下。只重启一个会让另一个留在旧答案上，且有那么一刻有两个源——或一个都没有。

检查哪个在带机器人：

```bash
systemctl is-active padd netpadd
```

```
inactive
active
```

`padd` inactive、`netpadd` active 是 UDP 手柄。反过来是蓝牙手柄。两个都 active 意味着其中一个是在旧答案上启动的：两个 unit 从同一个键选择，所以一次只重启了一个的手工编辑之后，另一个继续跑、直到它也被重启——重启两个，或用 `robotctl configure` 改键，它做的是后者。两个都不 active 意味着本该运行的那个失败了——`journalctl -u netpadd -b` 有原因。

回到蓝牙，设 `netpad.enabled = false`（或重置键）并重启同样两个 unit。一个读不了的配置算作关闭，所以一个损坏的文件从不让人失去手柄。

其他四个键都在启动时读，所以它们也要重启两个 unit：

| 键 | 默认 | 它是什么 |
|---|---|---|
| `enabled` | `false` | UDP 是手柄来源，`padd` 退下 |
| `port` | `4210` | UDP 端口，绑定 IPv4 `0.0.0.0` |
| `max_hz` | `30` | 每秒发往机器人的最多意图帧，10 到 100；超出被拒绝 |
| `stale_ms` | `300` | 这么久没有新东西，机器人原地停下，客户端保留；也是一个数据报可以迟到多久仍能驾驶。它必须低于 `[safety] deadman_ms`，否则配置被拒绝、错误点名两个键 |
| `timeout_ms` | `1000` | 此后的沉默让客户端算作消失；至少 `stale_ms`，否则配置被拒绝 |

## 从笔记本驾驶

```bash
duckctl udp-pad
```

没有地址时它像 `duckctl ip` 那样通过蓝牙找到机器人，所以 `--name` 和 `DUCK_ROBOT` 选哪一个。一个地址跳过那个、无需蓝牙也能工作：

```bash
duckctl udp-pad 192.168.1.42
```

在你想用来驾驶的手柄上按任意键：那个手柄就是它要发的，直到被拔掉。那次按下本身不作为按下发送。地址末尾的一个端口（`duck.local:4210`）覆盖默认，`--hz`（10 到 100，默认 30）是它每秒最多发送的。它一有变化就发、否则每 `1/hz` 一个保活，所以机器人能分辨一只静止的手柄和一只消失的手柄。笔记本上没有手柄时它什么都不发，机器人像对一只走掉的蓝牙手柄那样超时它。`Ctrl-C` 结束它：机器人 `stale_ms` 后停下，`timeout_ms` 后一秒坐下。

如果推摇杆向前让机器人倒退，加 `--invert-y`：它在发送前翻转两个摇杆的 Y。

### 一个笔记本驾驶多只鸭子

每只鸭子插一只手柄。每只鸭子开一个终端，在每个里各启动一个 `udp-pad`，一次一个。

在第一个终端：

```bash
duckctl udp-pad 192.168.1.42
```

给那只鸭子按手柄上的一个键。它的块现在显示手柄名。在第二个终端：

```bash
duckctl udp-pad 192.168.1.43
```

在第二只手柄上按一个键。每只鸭子都这样继续。

一只已经在驾驶鸭子的手柄会被跳过：再按它说它驾驶哪只鸭子……

```text
│ trig   LT ···············  +0.00   RT ███████████████  +1.00                │
│  A   B   X   Y   LB   RB   START   SELECT   UP   DOWN   LEFT   RIGHT   HOME │
│ last input 12 ms ago · values as sent, before the duck's deadzone           │
└ sending 30 Hz of 30 · 0 failed ─────────────────────────────────────────────┘
┌ log ────────────────────────────────────────────────────────────────────────┐
│ gamepad: Xbox 360 Controller — sending its state                            │
│ ● CONNECTED — driving the duck                                              │
└ q quit ─────────────────────────────────────────────────────────────────────┘
```

鸭子块在连接时绿、不连接或另一个客户端在驾驶时红——它的第一行说哪个以及为什么。按住的按键点亮。数字来自机器人的[应答](#机器人应答什么)：

| 鸭子块说 | 含义 |
|---|---|
| `● CONNECTED` | 机器人接收这台笔记本的数据报。`rtt` 是往返时间，`loss` 是过去一秒里机器人没计入的数据报占比，`stale` 是它因乱序或迟到而丢掉的那些 |
| `✕ REFUSED` | 另一个客户端在驾驶机器人，一次只能一个。这台笔记本被忽略，直到那个安静 `timeout_ms` 那么久，然后接管 |
| `✕ NOT CONNECTED` —— 没有监听 | 机器人的地址拒绝端口：那里没跑 `netpadd`，或 `[netpad] enabled` 关闭 |
| `✕ NOT CONNECTED` —— 停止应答 | 曾有应答、它们停了。WiFi、机器人重启、或 `netpadd` 重启 |
| `✕ NOT CONNECTED` —— 没有应答 | 发出去了、从没有回来的：错误的地址、防火墙、或一个比它的应答更旧的 `netpadd`——它仍能驾驶 |

机器人块是机器人自己的 `robot.health` 和姿态，和 `robotctl health` 及 monitor 的电源行同样的事实，用同样的规则着色。红：不健康、电池 15% 或更低、电机不应答、IMU 缺失或冻结、跌倒。黄：降级、电池 30% 或更低、电机总线读失败、CPU 节流、松软。舵机的温度显示但从不着色，因为机器人上没有任何东西定义多热算过热。`refused` 是你最后要求、机器人不做的那个，以及为什么——是「我按了、什么都没发生」的答案。每次告警（何时升起、何时清除）和每次拒绝也进日志。只有驾驶鸭子的客户端收到这些任何一条。

管道到文件时，它改为每 10 秒把同样的事实写成一行。

## 写你自己的发送端

一个数据报携带整个状态。每个字段小端，包是 28 字节：

| 偏移 | 大小 | 字段 | |
|---|---|---|---|
| 0 | 4 | magic | `b"DKPD"` |
| 4 | 1 | version | `1` |
| 5 | 1 | flags | 保留：发 0，接收方忽略它 |
| 6 | 4 | seq | u32，每数据报 +1，回绕 |
| 10 | 4 | t_ms | u32，发送端自己的时钟、以 ms 计、从任何地方开始；一个数据报到得多晚从它读出。`0` 意味着没有、什么都不检查 |
| 14 | 12 | axes | i16 ×6：lx ly rx ry（±32767 映射到 ±1，向上为正），lt rt（0..32767 映射到 0..1） |
| 26 | 2 | buttons | u16：位 0 A，1 B，2 X，3 Y，4 LB，5 RB，6 Start，7 Select，8 Up，9 Down，10 Left，11 Right，12 Home |

发原始摇杆值。机器人像对蓝牙手柄那样施加死区，所以一个自己施加的发送端会施加两次。`buttons` 的 13 到 15 位保留：接收方忽略它们并记一次日志。一个比 28 字节*长*的 version-1 包被接受、尾巴被忽略，所以以后可以加字段而不升版本。

一个 Python 发送端。它只要在驾驶就以每秒三十次发整个状态——一个暂停超过 `timeout_ms` 的发送端就是消失了，下一个数据报是一次新连接、其按键算作已按住，所以一次暂停后单独发出的按下什么都不做。它以一只中立的手柄开始，点一下 Start 让机器人站起来，它站立期间持续发静止的手柄，再点一次 Start 打开策略，向前走三秒，然后发一个机器人丢掉的过期数据报，接着沉默：

```python
import random, socket, struct, time
DUCK, START = ("duck.local", 4210), 1 << 6
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
seq = random.getrandbits(32)                  # 一个重启的发送端不会被误认为过期的
def pkt(seq, ly=0, buttons=0):
    t_ms = int(time.monotonic() * 1000) % 2**32
    return b"DKPD" + struct.pack("<BBII6hH", 1, 0, seq, t_ms, 0, ly, 0, 0, 0, 0, buttons)
def hold(frames, ly=0, buttons=0):            # 同样的状态，每 1/30 s
    global seq
    for _ in range(frames):
        seq = (seq + 1) % 2**32
        s.sendto(pkt(seq, ly, buttons), DUCK); time.sleep(1 / 30)
hold(10)                                      # 先是一只静止的手柄
hold(5, buttons=START); hold(60)              # 点 Start：robot.init，以及 2 秒站立
hold(5, buttons=START); hold(10)              # 再点 Start：策略打开
hold(90, ly=32767)                            # 向前 3 秒
s.sendto(pkt((seq - 50) % 2**32, ly=-32767), DUCK)  # 过期：被丢，从不会倒退
# 然后沉默：机器人在 stale_ms 后停下，timeout_ms 后一秒坐下
```

发送端遵循的规则，以及为什么：

- **每次发整个状态。** 什么都不重传、什么都不排队，所以一个丢的数据报必须无代价——而只有当下一个说了全部时它才无代价。
- **`seq` 从随机值开始、每数据报加 1。** 机器人丢掉一个不比上一个新的数据报，这正是乱序的那个从不把机器人往后带的原因，也丢掉一个比它超前 1000 多的，所以发送端绝不能跳着超前。随机开始意味着一个重启的发送端不会被误认为过期的。
- **`t_ms` 从一个单调时钟按毫秒打戳。** 机器人从不与它同步：它把每个数据报的投递与同一条流里见过的最快对比，所以任何起点都行，但一个会跳的时钟在被采纳前会读作迟到一秒。
- **一个状态并入下一个。** `max_hz` 限制意图去机器人的频率，一个在间隔内到达的变化等下一个时隙而不是被丢。一个在两个时隙之间先后落地的按下和释放仍会触发，因为按键按数据报比较、不按时隙。
- **一个迟到交付的数据报被丢。** Wi-Fi 能把数据报扣几秒再一次性放出来、按顺序，所以每个仍是最新的。一个比同一条流里见过的最快交付慢超过 `stale_ms` 的被丢并计为 stale，其中按下的按键什么都不触发：它说手柄做过什么、不是说在做什么。计数最多每 10 秒记一次。一条流是同一个发送端延续它的 `seq`，跨一次沉默也是，所以客户端算作消失后才到达的积压仍被丢，而它里一个重复或乱序的、在最后一个 `seq` 处或稍后一点的也是。一个重启的发送端、随机 `seq`，是一个新的，按它自己的时钟判定。整整一秒都以同样量迟到，是发送端的时钟动了、不是积压——积压成串排空，每个都比前一个迟到得少得多——于是该流被重新采纳。
- **数据报到得多晚被记录。** 一个客户端驾驶时每 10 秒，`netpadd` 记一行 `link:`：p50、p99 和超过该流最快交付的最大延迟（ms），以及多少因迟到被丢。几 ms 是健康链路。几百且没丢，是 `stale_ms` 之下的滞后；`late` 高于 0 是积压或超出它的滞后。`stalls` 是机器人在 `stale_ms` 里没有新东西而被停下的次数。
- **第一个发送端持有它。** 机器人锁到它接受的第一个数据报的地址，丢掉来自任何其他地址的数据报，直到那个沉默 `timeout_ms` 那么久，所以两个诚实地驾驶的人不会为一只鸭子打架。它不是保护：见[信任](#信任)。
- **一段短沉默停住机器人。** `stale_ms` 里没有可接受的之后，`netpadd` 立即停住行走、把头和身体姿态留在原地，且在再次听到客户端之前什么都不发——不是再发最后的摇杆，那会让 `robotd` 的 deadman 继续吃手柄做过的动作。客户端保留机器人：锁、进行中的长按和它的按键都在它回来时继续，所以它下一个数据报里的一次按下会触发。坏的 Wi-Fi 代价是一次停下、不是会话。
- **一段长沉默是客户端消失了。** `timeout_ms` 里没有可接受的之后，进行中的长按被重置、锁被释放。然后它做 `padd` 在蓝牙手柄掉线时做的：一秒后机器人问手柄去哪了（一个声音），如果站着就坐下，所以它不会被冻在房间中央。一台拒绝的机器人——踢到一半、起身到一半——被再问几秒，然后原样留下。它等待时，`robotd` 让它自己环顾。客户端回来时以另一个声音问候——只在机器人问过时：比那一秒短的闪断，坏 Wi-Fi 一分钟制造许多次，不出声。日志在每个方向以 `warn` 各说一次：`pad client connected` 和 `pad client gone`。
- **客户端消失之后、或 `netpadd` 启动之后的第一个数据报什么都不触发。** 它的按键被当作已按住，所以一个带着 Start 按下连上的客户端不把机器人站起来、也不坐下——回来时不、保持按下时不、松开时不。一段沉默后任何序号都被接受，所以一个重启的发送端在 `timeout_ms` 内被捡起：在旧的算作消失前，新发送端的随机 `seq` 可能读作 stale 而被丢。
- **畸形数据报被丢。** 错误的 magic、少于 28 字节、或未知版本：数据报被丢并计数，计数最多每 10 秒记一次，所以端口上的噪声物无法淹没日志。

`padd` 和 `netpadd` 恰好一个运行，因为每个都在启动前于其 unit 的 `ExecCondition=` 里问同一个配置键。为什么是那个而不是 `Conflicts=` 在 `netpadd/systemd/netpadd.service`，它与一次更新如何交互在 [`restart-order.md`](../design/restart-order.md)。

## 信任

没有。局域网上任何够得到 UDP 端口 4210 的人，一旦当前客户端安静了 `timeout_ms` 那么久，就能驾驶机器人——包括按住 Select 给它断电。一个客户端说话时，它的地址是唯一把别人挡在外面的东西，而局域网上的源地址能被伪造：一个携带驾驶者地址、`seq` 稍领先于他们的数据报会被当作他们的。1000 超前界限阻止一次盲目伪造把驾驶者锁出去，但挡不住一个能看到流量的人。在一条你会让人进到机器人房间里的网络上用它，超出那个的任何东西用 [WebRTC](../design/remote-webrtc.md)。
